# 備份管制與防護基準系統清冊整合設計 (2026-08-04)

## 目標
將原本「備份管制」讀取「資訊資產」來獲取系統名稱的行為，改為讀取「防護基準」的「系統清冊」。
同時，新增「系統ID」欄位至「備份管制」工作表，以便後續與其他系統精確整合。

## 方案決定
**方案 A (推薦)**：前端下拉選單合併顯示「系統ID - 系統名稱」，送出表單後，後端將字串拆分為獨立的「系統ID」與「系統名稱」欄位寫入。

## 修改範圍與技術細節

### 1. 環境設定 (`env.js`)
- **新增**：`SECURITY_BASELINE_SPREADSHEET_ID` 常數，用來存放「防護基準」Google Sheet 的檔案 ID。
- *註：待開發與部署前，需由使用者提供該檔案 ID 並手動填入。*

### 2. 選單資料來源切換 (`code.js` - `getAssetOptions`)
- **修改邏輯**：
  - 開啟 `SECURITY_BASELINE_SPREADSHEET_ID` 試算表，讀取 `系統清冊` 工作表。
  - 擷取 A 欄 (系統ID) 與 C 欄 (系統名稱)。
  - 若兩者皆有值，組合成字串 `系統ID - 系統名稱`，存入陣列傳給前端。

### 3. 表頭定義與欄位位移 (`code.js` - `EXPECTED_HEADERS` 等)
- **增加欄位**：在 `EXPECTED_HEADERS` 陣列的索引 1 位置（原「系統名稱」之前）插入 `'系統ID'`。
  - 新表頭順序：`['時間戳記', '系統ID', '系統名稱', '系統等級', '備份標的', ...]`。
- **欄位位移對應修改**：
  由於插入了一個欄位，原本讀取陣列索引 `row[n]` (`n >= 1`) 的地方都要加上 1，涵蓋以下函式：
  - `submitData`：處理更新與刪除比對時的 Target Key 索引 (從 `row[14]` 改為 `row[15]`)。
  - `getDashboardData`：解析系統名稱、等級、管理者等資料時的索引全部加 1 (如 `row[1]` 變 `row[2]`)。
  - `parseTargetFromRow`：讀取備份標的名稱、各週期、代數、異地存放資訊的索引全部加 1。
  - `generateBackupControlDocument`：產生表格資料時讀取所有欄位的索引全部加 1。

### 4. 寫入資料 (`code.js` - `buildSheetRowData_` & `submitData`)
- 前端 `formData.systemName` 會傳來如 `SYS-001 - 測試系統` 的字串。
- `submitData` 接收後，將其以 `' - '` 為分隔符拆解。
  - 左半部為 `systemId`。
  - 右半部為 `systemName`。
  - *邊界防護：若無分隔符，則整個字串當作系統名稱，ID 留空（或依約定處理）。*
- 將 `systemId` 傳入 `buildSheetRowData_`，並將其安插在陣列索引 1 的位置。

## 部署與遷移注意事項
- 系統上線後，使用者必須手動在現有的「備份管制」Google Sheet 的 B 欄 (時間戳記右方) 插入一欄空欄位，並命名為「系統ID」。
- 因為欄位數與順序改變，若不手動增加該欄，系統會讀取到錯位的資料，甚至觸發表頭修復邏輯。
