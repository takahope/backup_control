# 備份管制與系統清冊/資訊資產雙來源整合設計 (2026-08-04)

## 目標
在「新增設定」表單中，讓使用者能動態切換備份標的的來源為「防護基準的系統清冊」或是「外部資訊資產清單」。
同時將選取的 ID 與名稱分離寫入至「備份管制」工作表中的對應欄位，統一使用 `ID - 名稱` 的下拉選單格式。

## 方案決定
前端增加「來源切換」選項（Radio Button）。使用者先點選「來源：系統清冊 / 資訊資產清單」，下方的下拉選單就會根據選擇自動切換對應的清單。後端寫入時，若選擇資訊資產，也將資訊資產編號寫入「系統ID」欄位（該欄位將具備共用性質，作為 系統/資產 ID）。

## 修改範圍與技術細節

### 1. 後端選單資料擷取 (`code.js` - `getAssetOptions`)
- **雙來源讀取**：
  1. 讀取 `SECURITY_BASELINE_SPREADSHEET_ID` 的 `系統清冊` 工作表。
  2. 讀取 `ASSETS_SPREADSHEET_ID` 的 `資訊資產清單` (備用名稱：`資訊資產`) 工作表。
- **資料處理與回傳格式**：
  - 兩份工作表皆抓取 A 欄 (ID) 與 C 欄 (名稱)。
  - 將其組合為 `ID - 名稱` 的字串陣列。
  - 回傳資料結構修改為：`{ success: true, data: { systems: [...], assets: [...] } }`。

### 2. 前端畫面與互動修改 (`Index.html`)
- **HTML 結構調整**：
  - 在新增表單的「系統名稱」輸入框上方，增加一組 Radio Button 區塊：
    - `(◉) 系統清冊` (預設)
    - `( ) 資訊資產清單`
  - 調整輸入框旁的文字標籤，從「系統名稱」微調為「系統 / 資訊資產」。
- **JavaScript 選單動態切換邏輯**：
  - 頁面載入並呼叫 `loadAssetOptions` 收到資料後，將 `systems` 與 `assets` 陣列分別儲存。
  - 初始化載入時，將 `<datalist>` (系統選單來源) 填入 `systems` 的內容。
  - 監聽 Radio Button 的 `change` 事件：當使用者切換為「資訊資產清單」時，清空 `<datalist>` 並動態填入 `assets` 的選項；反之亦然。

### 3. 表單寫入邏輯相容性 (`code.js` - `submitData` & `buildSheetRowData_`)
- 由於前端選單送出表單的字串皆為一致的 `ID - 名稱`，目前後端 `submitData` 中以 `' - '` 字串拆解為 `systemId` 與 `parsedSystemName` 的邏輯可完美共用，不需要改動。
- 不論是系統清冊還是資訊資產，其擷取出的 ID 皆會寫入原本新擴充的 B 欄 (系統ID)。

## 後續執行
完成本次實作後，系統就能彈性地在兩個資料庫中切換。但需注意，實體 Google Sheet 中的表頭建議手動改名為「系統/資產ID」及「系統/資產名稱」，以符合實際存入的資料意涵。
